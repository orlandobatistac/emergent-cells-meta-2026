# Provenance, disclosure and intellectual-property boundary

## Separate projects

- Pre-existing private research: `orlandobatistac/emergent-cells-lab` (do not copy or expose without explicit review).
- Public new-work submission: `orlandobatistac/emergent-cells-meta-2026`.

The **ideas** of local rules, modular growth, physical energy budgets, local learning and substrate independence were investigated before the hackathon. Historical experiments, source files and measured results are **prior work**. This project's implementation must be newly developed during the eligible build window and visibly distinguishable.

## Public repo safeguards

- No proprietary/private experiments, screenshots of private research, private prompts, access tokens, participant login info or other personal data.
- No third-party model weights, graphics, datasets or transcripts without confirmed rights.
- Avoid suggesting open licensing without a LICENSE file. Select a license deliberately once IP implications are reviewed.
- Document exactly which files were created during the competition; consider a dated release tag for the submission.
- Document any dependency's license and any reused open-source component.
- Review event rules and waiver for ownership, media and code licensing before publishing additional material.

## Claims

A Python simulator cannot establish physical joules, physical replication, brain-like cognition, general intelligence or genuine substrate independence. Scientific language must separate hypotheses, simulation outcomes and demonstrated engineering.

Historical results from the private project may motivate comparisons, but they cannot be described as new hackathon achievements.
