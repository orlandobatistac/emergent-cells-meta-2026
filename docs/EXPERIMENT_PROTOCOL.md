# Reproducible evaluation protocol — draft v0

This is a preregistration-style **plan**, not experimental results. Freeze final metrics and evaluation splits before collecting claim-bearing results.

## Central question

Can locally interacting, resource-constrained cells acquire behavior that improves survival/adaptation, and do Meta-designed worlds provide more informative scientific tests than non-Meta worlds?

## Comparisons

- **Control 0**: same actuator/world interface; untrained cells / random motor output, matched for steps and energy.
- **Control 1**: local cells with plasticity off / fixed connectivity.
- **Treatment 1**: local learning enabled.
- **Treatment 2**: treatment 1 with structural plasticity (if stable).
- **Treatment 3**: treatment 2 with local growth (if stable).
- Independently cross with human-fixed, random-procedural and Meta-generated worlds, with and without Meta adaptive sequencing.

Do not blend all factors into a single experiment; factorial comparisons must match total training interactions.

## Primary outcomes

1. Survival fraction/time to failure on held-out worlds.
2. Change in net harvested resource and remaining local energy.
3. Recovery latency after an environmental/sensor perturbation.
4. Robustness across novel worlds, seeds and intervention strengths.

## Instrumentation & honesty

- Raw per-episode records: seed, config hash, model/world provenance, time horizon, rewards/resource exchanges, cell count, motion, interventions and failure reasons.
- Report all runs; mean, spread and per-seed table; include negative results.
- CPU time and number of cell updates/message passes are **software-cost proxies**.
- Simulated metabolic units are **model-dependent energy proxies**, not SI joules.
- Growth and local plasticity are features to be validated, not presumed accomplishments.

## Reproducibility gates

- Same WorldSpec and seeds must yield identical results without external service dependencies.
- Consistent interfaces across controls and treatments.
- Predefine held-out seeds; never tune an algorithm against those outcomes.
- Instrument no learning when plasticity is explicitly disabled.
- Test zero-energy and no-resource behavior.
- Verify limits: energy >= 0, finite weights/activity, bounded cells, conservation except documented sinks/sources.
- Failure / success classification not generated by LLM.
- Do not quote pre-event research metrics as new competition results.

## Release reporting

Publish a methods document, explicit assumptions and a reproduction command with pinned dependencies, hardware/OS notes, run duration and expected checksum if practical.
